# B2 input contract and privacy

Only manifest.json and encounter.json schema 1.0 exports are supported. Selected File objects are read after explicit consent; no upload or persistence is implemented. Limits apply before read: 16 KiB manifest / 4 MiB payload. The parser rejects unsafe property names, excessive nesting/complexity, invalid UTF-8/JSON, unsupported schema/orbit/frame/units/epochs, incomplete rows, non-finite/implausible states, duplicate/gapped timestamps, missing source metadata, inconsistent event values and false producer acceptance reports.

The supported source contract is the existing orbit-220 reconstruction: Earth center 500@399; target 99942; ICRF, FRAME, geometric NONE; KM-S; TDB; source signatures Horizons 1.2/1.3, CAD 1.5, SBDB 1.3. Coarse/fine counts and cadences are version-specific. Data schemas changing legitimately still require validation before support is expanded. Original scientific tolerances are not edited by input validation.

A raw-payload SHA-256 verifies bytes against a manifest. Self-consistent manifests and provenance fields are not proof of origin. The application separately compares the payload with the fixed maintainer-reviewed historical export digest. Only that exact byte match earns HISTORICAL BYTE MATCH; other compatible inputs remain UNVERIFIED LOCAL DATA. It is not a NASA/JPL signature or a new scientific certification. Missing/incompatible provenance is rejected as unverified rather than rendered as official data.

The public app contains no historical payload, private observations or result tables. A fixed integrity digest alone does not encode the trajectory. The local workflow does not grant data redistribution rights. Clear local data or reload to release app-held references; browser/OS allocation retention may differ from object liveness. No analytics, cookies, IndexedDB, localStorage, service worker or server ingest is used by this application. Local test fixtures remain outside the public source/build tree.
